Security & data handling

As of 12 November 2026.

Hosting and transport

  • Cortex pages and APIs run on Cloudflare Workers.
  • Traffic is served over HTTPS (TLS). Plain-HTTP requests are redirected to HTTPS. HSTS is sent.

What is stored, and where

  • Each Cortex page stores its working data in the viewer's own browser (localStorage) on that device.
  • That storage is not separately encrypted by Cortex. It is protected by the device and browser.
  • Cortex's servers do not store request text for these workflows and do not write it to application logs.
  • No database holds St. Catherine's data.

Third parties that receive data

  • Cloudflare, as host.
  • TypeSafe, an AI classification API. It receives request text that passed the local identifier check, for classification only.
  • No other third parties for this workflow.

Secrets

  • API keys are held as Cloudflare Worker secrets, not in page code.

HIPAA and BAA

  • No Business Associate Agreement is in place with St. Catherine's.
  • No BAA is in place between Pitch, Pray, Ship and Cloudflare or TypeSafe for this service.
  • Therefore Cortex must not receive PHI.
  • The product enforces this with a two-stage identifier gate: browser and server. When identifiers are detected, the text is not sent onward, stored, shown or logged.
  • No automated check catches every identifier, so staff should still not enter patient information.

How to verify

  • Use the browser DevTools Network tab to see what is sent.
  • Run the "Prove it" self-test on the St. Catherine's page.
